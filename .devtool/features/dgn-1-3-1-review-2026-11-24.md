# godoodungeon 1.3.1: Release review

Ships several path sockets and the Doorway Socket (card `dgn-1-3-1-doorway-socket-2026-11-24`, brief §14.1). Only godoodungeon changes; the shared solver stays as in godoowave 1.6.0.

## Done when
- `addons/godoodungeon/plugin.cfg` is 1.3.1, and the root README names `godoodungeon-1.3.1.zip`.
- The CHANGELOG 1.3.1 entry says one Path Socket name and an empty Doorway Socket give the same dungeon as 1.3.0.
- The PR is merged and the tag `godoodungeon-v1.3.1` is pushed on the merge commit; the *Release addon* workflow passes and publishes the release.

## Review checklist for the board
1. Build, focus Godot so it reloads the C# assembly, then toggle **godoodungeon**.
2. The dialog shows **Doorway Socket** below Path Socket, empty, with the placeholder "any path socket".
3. Generate the demo dungeon with the default settings: same result as 1.3.0 for the same seed.
4. In a corridor tile set with `corridor` and `pitfall` pieces (corridor faces `corridor, pitfall`, a pitfall straight with `pitfall`), set Path Socket `corridor, pitfall` and Doorway Socket `corridor`: Generate over a few seeds puts no pitfall right outside a door, but pitfalls appear in the corridors.
5. Set Doorway Socket `lava`: the status shows the error that it is not in Path Socket, and Generate is refused.
