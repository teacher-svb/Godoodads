# godoodungeon 1.1: Release review

Demo for the board. The board moves this card to *Done* when approved, after which the release is tagged `godoodungeon-v1.1.0`.

## Review checklist for the board
1. Generate a dungeon, turn on Preview Layout and compare the room numbers with the graph in the GridMap metadata.
2. Undo, redo and Clear Dungeon; check the graph follows.
3. Play the graph demo: start, end and path rooms marked, distances printed.
4. Read the README section and the acceptance results.
5. Do the manual checks on `dgn-1-1-graph-write` and `dgn-1-1-preview-labels` (both in *Review*).
6. Optional, for §12.6 item 6: export `dungeon_graph.tscn` as a game (needs the 4.7 .NET export templates) and run it; the console prints the way.

## Before tagging
- Merge `godoodungeon-1.1-graph` to main, then push `godoodungeon-v1.1.0` on the merge commit; the *Release addon* workflow publishes it.
- If the tag is pushed after 2026-11-20, change the CHANGELOG date.

## Code review (2026-11-20, stern-reviewer)
Verdict: approve, two minor findings, both fixed:
1. `ShortestPath` ties did not follow "fewer hops, then lower indices": Dijkstra's predecessor order decided, and the answer depended on direction (0-1-3 = 3 + 7 vs 0-2-3 = 2 + 8 gave [0, 2, 3]). `Path` now walks from `from` over shortest ways only, taking the lowest next room (then corridor), which gives the lowest room list. Asymmetric and mirrored tie tests added; the demo's path is unchanged.
2. Brief §12.6 item 1 named `DungeonGraph.Of`; now `StoredOn`.
Core 510/510, engine 134/134.
