# godoodungeon 1.1: Graph demo scene

Demo scene with a generated dungeon and a GDScript that, at runtime, takes `Diameter()` as start and end, marks both rooms and the rooms on the shortest path, and prints hop and corridor distances. Added to the demo build scene.

Brief: §12.5, §12.6 item 6.

## Done when
- Runs headless from a clean checkout with the plugin disabled and prints the expected path.
- Manual (review): markers visible when the scene is played.

## Results (2026-11-20)
- `demo/godoodungeon/dungeon_graph.tscn`, built by `BuildDungeonDemo.SaveGraphDemo` (the existing build scene, now 3 scenes): a 48 × 48 dungeon of 12 rooms (Extra Connections 0.25, seed 1) generated at build time and saved with its cells, markers, record, settings and graph; a top-down orthographic camera; `graph_demo.gd` on the root. Lighting moved into `AddLighting`. Rebuilding the other demo assets only changed random node ids, so those files were left as committed.
- `demo/godoodungeon/graph_demo.gd`: reads the graph with `get_meta`, takes `Diameter()` as start and goal, sets their `Data["role"]`, puts a disc and a label ("Room 3 / 0 hops · 0 cells") on every room (green start, red goal, gold path) and a gold dot on every path corridor cell, under a `GraphMarkers` node, and prints the way. Untyped `var graph` on purpose: a fresh checkout's class cache may not know `DungeonGraph` yet.
- Run as a game, headless, without the editor or plugin: "Dungeon graph: 12 rooms, 14 corridors. Start room 3, goal room 12: 6 corridors and 54 corridor cells apart, through rooms 3, 6, 10, 7, 8, 2, 12." (§12.6 item 6). A rendered frame (Movie Maker) shows the markers and readable labels on the path.
- Engine test `The_graph_demo_reads_its_baked_graph_and_marks_the_way`: the baked graph equals what the stored settings generate (§12.6 item 5), `RoomAtCell` on every room centre, and running the scene sets the roles and adds rooms + path cells markers. Engine suite 134/134, Core 510/510.
