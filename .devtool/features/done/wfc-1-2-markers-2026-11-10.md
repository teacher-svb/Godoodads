# WFC 1.2: Marker tiles

Optional `Marker` PackedScene on `WfcTile`. After a successful solve, instance it at each generated cell with the cell transform, under a `WfcMarkers` child of the GridMap owned by the edited scene, tagged with metadata. Generate removes the tagged markers inside the bounds first. All in the same undo action.

Brief: §12.4.

## Done when
- Engine tests: markers are placed with the right transform for each rotation, empty tiles can carry markers, regenerate removes only tagged markers inside the bounds, undo and redo restore them, hand-placed cells get no markers.
- Markers are saved with the scene and survive reopening it (manual check).

## Result
- `WfcTile.Marker` (PackedScene), `TileSetBinding.Markers`, and `Adapters/GridMapMarkers`: `Plan` (free cells only, cell centre plus the GridMap basis for the rotation), `Replaced` (tagged markers whose current cell is a free cell in the bounds) and `Instantiate` (tags with `godoodads_wfc_marker`; returns null when the scene root is not a Node3D).
- The plugin adds the marker changes to the generation's undo action: it creates the `WfcMarkers` container if needed, removes replaced markers and adds new ones, each owned by the edited scene root, with do and undo references. The status reports placed and replaced markers, and skipped scenes.
- Refinement (brief §12.4 updated): markers on cells that stay (hand-placed, edited, pinned) stay with them. Markers on regenerated cells are always replaced, even moved ones.
- Tests: 4 engine tests (transform per rotation, empty tiles, no markers on fixed cells, only tagged markers on regenerated cells are replaced, round-trip).
- Waiting on: the manual check of save and reopen, undo and redo, and regenerate.
