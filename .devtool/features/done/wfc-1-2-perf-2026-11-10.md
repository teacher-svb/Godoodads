# WFC 1.2: Recover synthetic performance

Profile the remaining-weight bookkeeping in `WfcSolver` (`Narrow`, `SetCount`, `Undo`) and reduce its cost.

Brief: §12.5.

## Done when
- The 25- and 50-tile synthetic sets are within 10% of 1.0 (0.73 s and 1.55 s), or the measured gap is reported for the board.
- Results for a seed do not change (or the change is noted in the CHANGELOG).

## Result
- Trimming the weight bookkeeping did not help: skipping zero bytes in `WordMass` and removing a branch in `BucketOf` were within noise. The 1.1 gap was the different search path, not the bookkeeping.
- Fix: propagation now ORs one compatibility row per **class** of variants with identical rows in a direction (`CompiledTileSet.ClassStart`, `ClassMembers`, `ClassRows`), instead of one per variant. Few socket labels means few classes. The allowed mask is identical, so **results do not change**: the demo gives the same tile counts per seed, and the synthetic sets the same backtrack counts.
- Synthetic sets, 1.0 → 1.1 → 1.2: 25 tiles 0.73 → 0.86 → 0.70 s, 50 tiles 1.55 → 1.77 → 1.10 s, 12 tiles 4.79 → 4.9 → 3.55 s.
- Demo at 100×16×100, 20 seeds: ground 1.65 → 0.66 s, free 2.34 → 0.81 s, 20 of 20, identical results.
