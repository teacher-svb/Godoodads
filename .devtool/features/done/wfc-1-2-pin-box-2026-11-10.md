# WFC 1.2: Pin box

A pin box in `WfcSettings` (origin and size) drawn in its own colour with the same handles. **Pin** removes the generated cells inside it from the regenerate record; **Unpin** adds unchanged cells back. One undo action each.

Brief: §12.3.

## Done when
- Engine tests: pinned cells are kept by the next Generate, unpinned cells are replaced, undo restores the record.
- The status reports how many cells were pinned or unpinned (manual check).

## Result
- `GeneratedRecord` entries have a pinned flag, stored in the top bit of the orientation byte (1.1 data reads as unpinned). Pinned cells that still match count as hand-placed (`FixedCells.Pinned`), and `RecordAfter` keeps pinned entries inside the bounds.
- `WfcSettings` Pin Box group: Origin and Size (0 hides it) plus Place Around Bounds, Pin Generated Cells and Unpin buttons, which raise `PinRequested`. The plugin pins or unpins the cells in the box that still match, as one undo step via `ApplyRecord`, and reports the count. The box has its own handles and a blue outline.
- Generate status: "Kept N existing cells, including M pinned cells".
- Tests: 2 Core tests (flag round-trip, filter, keeping pins) and 1 engine test (pin, edited cell not counted, ReadFixed, RecordAfter keeps pins, unpin). 190 Core and 47 engine tests pass.
- Waiting on: the manual check.

## Result
- Manual check passed (2026-11-10): Pin keeps the pinned part through a regenerate with a new seed, and Unpin releases it. (Placing the pin box worked through Place Around Bounds and the inspector; dragging is tracked on `wfc-1-2-bounds-handles`.)
