# godoodungeon 1.2: Room boxes: layout around fixed rooms

`LayoutGenerator` takes the boxes (footprint, height, mode, built door cells): checks of §13.2 as errors, boxes first in child order, generated rooms fill Room Count minus the boxes with the Gap from boxes, boxes in the room graph, door placer for Generated boxes, given doors for Built boxes (best-facing door per edge, extra loop edge for a door no edge uses), lane and entry rules for all doors. Layout attempts vary only the generated rooms.

Brief: §13.2.

## Done when
- Core tests: each check of §13.2; Room Count with fewer, equal and more boxes; boxes keep their numbers across seeds; every Built door gets an edge; blocked Built door lane is an error naming the box; determinism with boxes; layouts without boxes unchanged for the same seed (1.1 regression).

## Results (2026-11-20)
- `Core/RoomBoxes.cs`: `RoomBoxSpec` (Name, layout `Rect`, `Layer` relative to the bounds' bottom, `Height`, `Mode`, Built `DoorCells`); `RoomBoxes.BuiltDoors` (ring cells that are not corners, side from the ring); `RoomBoxes.Validate` with every check of §13.2 that does not depend on generated rooms, each naming "Room box `Name` (room n)"; also a box not on the bottom layer or taller than the bounds (`LayoutSettings.BoundsHeight`, set from the settings).
- `DungeonLayout`: `Boxes` (rooms 0…n−1), `RoomHeight`, `BoxOf`, `IsBuilt`, `Height(room)`, `Describe(room)`.
- `RoomPlacer`: boxes first, then Room Count − boxes generated rooms with the Gap from boxes; a warning when boxes outnumber Room Count. Same random stream without boxes. `LayoutValidator.Validate(settings, boxes)`: boxes count towards the 2-room minimum.

Generated boxes use the normal door placer.
